Clarity & Simplicity Illustration

  • Provide clear feedback for actions

Visual Hierarchy Guidelines

Visual hierarchy guides users through the interface, highlighting important elements and creating a clear path for the user's attention.

Size & Scale

Size & Scale Example

Use size to indicate importance. Larger elements draw more attention and should be used for primary actions and content.

  • Primary actions: Largest
  • Secondary actions: Medium
  • Tertiary actions: Smallest

Color & Contrast

Color & Contrast Example

Use color strategically to guide attention. High-contrast elements stand out while low-contrast elements recede.

  • Primary actions: Brand colors
  • Secondary actions: Neutral colors
  • Disabled states: Low contrast

Spacing & Proximity

Spacing & Proximity Example

Group related elements together and use spacing to create distinct sections. Proper spacing improves readability and comprehension.

  • Related items: Close proximity
  • Unrelated items: Greater spacing
  • Section breaks: Largest spacing

Typography Hierarchy

Typography Hierarchy Example

Use typography to establish hierarchy. Vary font weight, size, and style to differentiate between content types.

  • Headings: Larger, bolder
  • Subheadings: Medium weight
  • Body text: Regular weight
  • Captions: Smaller, lighter

Grid System

Our grid system provides a flexible foundation for layout design across all screen sizes.

Base Grid

Base Grid Illustration

Our base grid uses a 12-column layout with responsive breakpoints:

  • Column width: Flexible
  • Gutter width: 24px (adjusts at breakpoints)
  • Margin width: 5% of viewport (min: 16px)

Grid Implementation

/* CSS Grid Implementation */ .grid-container { display: grid; grid-template-columns: repeat(12, 1fr); gap: 24px; padding: 0 5%; } /* Example column spans */ .col-4 { grid-column: span 4; } .col-6 { grid-column: span 6; } .col-12 { grid-column: span 12; }

Use the grid system to create consistent layouts that adapt to different screen sizes.

Breakpoints

Our responsive grid uses the following breakpoints:

  • Mobile: 0-767px
  • Tablet: 768px-1023px
  • Desktop: 1024px-1439px
  • Large Desktop: 1440px+

Grid Behavior

The grid adapts to different screen sizes:

  • Mobile: Stacked columns (12 spans)
  • Tablet: Reduced column spans
  • Desktop: Full grid implementation
  • Large Desktop: Max-width container

Alignment Principles

Alignment Principles Illustration

Follow these alignment principles for consistent layouts:

  • Align text and components to a common edge
  • Use consistent text alignment within sections
  • Align related elements to create visual connections
  • Maintain consistent baseline alignment for text

Common Alignment Patterns

Use these common alignment patterns:

  • Form fields: Left-aligned labels, inputs full width

  • Lists: Left-aligned with consistent indentation
  • Headers: Left-aligned with content
  • Icons: Vertically centered with associated text

Screen Density

Screen density refers to the amount of content and spacing on the screen. Appropriate density improves usability and readability.

Density Guidelines

Density Guidelines Illustration

Follow these guidelines for appropriate screen density:

  • Maintain sufficient whitespace between elements
  • Group related elements together
  • Limit the number of elements on screen
  • Use progressive disclosure for complex interfaces
  • Adjust density based on screen size and context

Density Variations

Different contexts may require different density settings:

  • Compact: For data-heavy interfaces (tables, dashboards)
  • Standard: For most application interfaces
  • Comfortable: For content-focused interfaces
Density Variations Illustration

Touch Targets

Ensure appropriate touch target sizes for interactive elements:

  • Minimum size: 44px × 44px
  • Minimum spacing: 8px between targets
  • Primary actions: Larger touch targets
  • Destructive actions: Separated from other actions

Content Density

Balance content density with readability:

  • Line length: 50-75 characters per line
  • Line height: 1.5 for body text
  • Paragraph spacing: At least 1.5× the font size
  • Section spacing: At least 2× the font size

Component States

Components can exist in different states. Consistent state styling helps users understand the current status of the interface.

Interactive States

All interactive components should have the following states:

  • Default: The normal state of the component
  • Hover: When the cursor is over the component
  • Focus: When the component has keyboard focus
  • Active/Pressed: When the component is being clicked/tapped
  • Disabled: When the component is not available for interaction
Interactive States Illustration

State Implementation

/* Button States Example */ .btn { background-color: var(--primary-blue); color: white; transition: all 0.2s ease; } .btn:hover { background-color: var(--primary-blue-dark); transform: translateY(-2px); } .btn:focus { outline: none; box-shadow: 0 0 0 3px rgba(0, 162, 229, 0.3); } .btn:active { transform: translateY(1px); } .btn:disabled { background-color: var(--neutral-gray); color: var(--neutral-gray-dark); cursor: not-allowed; transform: none; }

Content States

Content components can have the following states:

  • Loading: When content is being fetched
  • Empty: When no content is available
  • Error: When content failed to load
  • Partial: When only some content is available
  • Loaded: When all content is available
Content States Illustration

Validation States

Form components can have the following validation states:

  • Default: Before user interaction
  • Focus: During user interaction
  • Valid: When input meets requirements
  • Invalid: When input fails validation
  • Warning: When input needs attention

Animation & Motion

Animation and motion help users understand state changes, provide feedback, and create a more engaging experience.

Animation Principles

Animation Principles Illustration

Follow these principles for effective animations:

  • Purpose: Animation should serve a purpose, not just decorate
  • Subtlety: Animations should be subtle and not distracting
  • Consistency: Use consistent timing and easing across similar animations
  • Performance: Optimize animations for performance
  • Accessibility: Respect user preferences for reduced motion

Animation Types

Animation Types Illustration

Common animation types in our applications:

  • Transitions: Smooth changes between states
  • Feedback: Visual confirmation of user actions
  • Loading: Indicate content is being loaded
  • Attention: Draw attention to important elements
  • Orientation: Help users understand spatial relationships

Animation Timing

Use consistent timing for animations:

  • Extra Short: 100ms (micro-interactions)
  • Short: 200ms (button states, toggles)
  • Medium: 300ms (transitions, reveals)
  • Long: 500ms (page transitions, complex animations)
/* Animation Timing Variables */ :root { --animation-xs: 100ms; --animation-sm: 200ms; --animation-md: 300ms; --animation-lg: 500ms; } /* Example usage */ .button { transition: all var(--animation-sm) ease-out; } .page-transition { transition: all var(--animation-lg) cubic-bezier(0.4, 0, 0.2, 1); }

Easing Functions

Use appropriate easing functions for different animation types:

  • Ease-out: For elements entering the screen
  • Ease-in: For elements exiting the screen
  • Ease-in-out: For elements moving within the screen
  • Linear: For continuous animations (loading spinners)
/* Easing Function Variables */ :root { --ease-in: cubic-bezier(0.4, 0, 1, 1); --ease-out: cubic-bezier(0, 0, 0.2, 1); --ease-in-out: cubic-bezier(0.4, 0, 0.2, 1); } /* Example usage */ .enter-animation { transition: all 300ms var(--ease-out); } .exit-animation { transition: all 300ms var(--ease-in); }

WCAG Principles

Our applications follow the Web Content Accessibility Guidelines (WCAG) 2.1 AA standards, which are organized around four principles: Perceivable, Operable, Understandable, and Robust.

Perceivable

Perceivable Illustration

Information and user interface components must be presentable to users in ways they can perceive:

  • Text Alternatives: Provide text alternatives for non-text content
  • Time-based Media: Provide alternatives for time-based media
  • Adaptable: Create content that can be presented in different ways
  • Distinguishable: Make it easier for users to see and hear content

Operable

Operable Illustration

User interface components and navigation must be operable:

  • Keyboard Accessible: Make all functionality available from a keyboard
  • Enough Time: Provide users enough time to read and use content
  • Seizures: Do not design content in a way that is known to cause seizures
  • Navigable: Provide ways to help users navigate and find content
  • Input Modalities: Make it easier to use inputs other than keyboard

Understandable

Understandable Illustration

Information and operation of the user interface must be understandable:

  • Readable: Make text content readable and understandable
  • Predictable: Make web pages appear and operate in predictable ways
  • Input Assistance: Help users avoid and correct mistakes

Robust

Robust Illustration

Content must be robust enough to be interpreted by a wide variety of user agents, including assistive technologies:

  • Compatible: Maximize compatibility with current and future user agents
  • Parsing: Ensure proper markup for assistive technologies
  • Name, Role, Value: Ensure proper identification of UI components

Keyboard Navigation

All functionality must be accessible using only a keyboard, without requiring specific timings for individual keystrokes.

Focus Management

Focus Management Illustration

Proper focus management is essential for keyboard navigation:

  • Focus Indicators: Provide clear visual focus indicators
  • Focus Order: Ensure logical focus order that follows content flow
  • Focus Trapping: Trap focus within modal dialogs and overlays
  • Focus Restoration: Restore focus when dialogs are closed
  • Skip Links: Provide skip links for navigation

Keyboard Interactions

Keyboard Interactions Illustration

Standard keyboard interactions for common components:

  • Tab: Move focus to the next focusable element
  • Shift+Tab: Move focus to the previous focusable element
  • Enter/Space: Activate the focused element
  • Arrow Keys: Navigate within components (e.g., menus, tabs)
  • Escape: Close dialogs, menus, or cancel actions

Custom Components

When creating custom components, ensure proper keyboard support:

  • Use appropriate ARIA roles and properties
  • Implement expected keyboard interactions
  • Test with keyboard-only navigation
  • Follow established patterns for similar components

Screen Reader Support

Applications must be compatible with screen readers and other assistive technologies.

Semantic HTML

Semantic HTML Illustration

Use semantic HTML elements to provide structure and meaning:

  • Use heading elements (<h1> to <h6>) for headings
  • Use <button> for buttons, <a> for links
  • Use <nav>, <main>, <section>, etc. for page structure
  • Use <ul>, <ol>, <dl> for lists
  • Use <table> for tabular data with proper headers

ARIA Attributes

ARIA Attributes Illustration

Use ARIA attributes when semantic HTML is not sufficient:

  • Use aria-label or aria-labelledby for labeling elements
  • Use aria-describedby for additional descriptions
  • Use aria-expanded, aria-haspopup for interactive elements
  • Use aria-live regions for dynamic content
  • Use appropriate ARIA roles for custom components

Alternative Text

Provide alternative text for non-text content:

  • Use alt attributes for images
  • Use aria-label for icons and SVGs
  • Provide captions and transcripts for audio and video
  • Make decorative images presentational with alt=""
  • Ensure alternative text conveys the same information as the visual content

Testing with Screen Readers

Test with popular screen readers to ensure compatibility:

  • NVDA: Free screen reader for Windows
  • JAWS: Commercial screen reader for Windows
  • VoiceOver: Built-in screen reader for macOS and iOS
  • TalkBack: Built-in screen reader for Android
  • Narrator: Built-in screen reader for Windows

Responsive Design Principles

Follow these principles to create responsive applications that work well across all devices.

Fluid Layouts

Fluid Layouts Illustration

Use fluid layouts that adapt to different screen sizes:

  • Use relative units (%, em, rem) instead of fixed units (px)
  • Use CSS Grid and Flexbox for flexible layouts
  • Set maximum widths to prevent overly stretched layouts
  • Use viewport units (vw, vh) for responsive sizing
  • Maintain appropriate aspect ratios for media

Responsive Images

Responsive Images Illustration

Optimize images for different screen sizes and resolutions:

  • Use the srcset attribute for responsive images
  • Use the picture element for art direction
  • Set appropriate image dimensions
  • Use SVGs when possible for resolution independence
  • Optimize images for performance

Content Prioritization

Content Prioritization Illustration

Prioritize content based on screen size and user needs:

  • Show the most important content first
  • Hide or collapse secondary content on smaller screens
  • Use progressive disclosure for complex information
  • Adjust content hierarchy for different screen sizes
  • Consider different user contexts on different devices

Touch-Friendly Design

Touch-Friendly Design Illustration

Design for touch interactions on mobile devices:

  • Use appropriate touch target sizes (minimum 44×44px)
  • Provide sufficient spacing between interactive elements
  • Place important actions within easy reach
  • Support common touch gestures (tap, swipe, pinch)
  • Provide visual feedback for touch interactions

Breakpoints

Use consistent breakpoints to create responsive layouts that adapt to different screen sizes.

Standard Breakpoints

Standard Breakpoints Illustration

Our standard breakpoints are based on common device sizes:

  • Small Mobile: 0-479px
  • Mobile: 480-767px
  • Tablet: 768-1023px
  • Desktop: 1024-1439px
  • Large Desktop: 1440px+

Breakpoint Implementation

/* CSS Variables for Breakpoints */ :root { --breakpoint-sm: 480px; --breakpoint-md: 768px; --breakpoint-lg: 1024px; --breakpoint-xl: 1440px; } /* Media Queries */ @media (min-width: 480px) { /* Small Mobile styles */ } @media (min-width: 768px) { /* Tablet styles */ } @media (min-width: 1024px) { /* Desktop styles */ } @media (min-width: 1440px) { /* Large Desktop styles */ }

Component-Specific Breakpoints

Use component-specific breakpoints when necessary:

  • Base breakpoints on content needs rather than device sizes
  • Consider the natural breaking points of each component
  • Use additional breakpoints for complex components
  • Test components at various screen sizes
  • Document component-specific breakpoints

Testing Breakpoints

Testing Breakpoints Illustration

Test responsive designs at various screen sizes:

  • Test at standard breakpoints
  • Test at in-between sizes
  • Test with browser developer tools
  • Test on actual devices when possible
  • Test in both portrait and landscape orientations

Mobile-First Approach

We follow a mobile-first approach to responsive design, starting with the mobile experience and progressively enhancing for larger screens.

Mobile-First Benefits

Mobile-First Benefits Illustration

Benefits of the mobile-first approach:

  • Forces focus on core content and functionality
  • Ensures good performance on mobile devices
  • Simplifies progressive enhancement
  • Aligns with how CSS naturally works
  • Addresses the growing mobile user base

Mobile-First Implementation

/* Base styles for all devices */ .container { padding: 1rem; } /* Tablet and up */ @media (min-width: 768px) { .container { padding: 2rem; } } /* Desktop and up */ @media (min-width: 1024px) { .container { padding: 3rem; max-width: 1200px; margin: 0 auto; } }

Layout Adaptations

Layout Adaptations Illustration

Common layout adaptations for different screen sizes:

  • Mobile: Single column, stacked elements
  • Tablet: Two columns, simplified navigation
  • Desktop: Multi-column, expanded navigation
  • Large Desktop: Wider content, optimized spacing

Navigation Patterns

Navigation Patterns Illustration

Responsive navigation patterns:

  • Mobile: Hamburger menu, bottom navigation
  • Tablet: Collapsed navigation, tabs
  • Desktop: Horizontal navigation, mega menus
  • Large Desktop: Expanded navigation with additional features
